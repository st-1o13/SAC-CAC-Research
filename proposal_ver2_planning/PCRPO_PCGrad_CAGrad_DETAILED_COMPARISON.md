## 1. 各手法の数学的定式化

### 1.1 PCGrad（Yu et al., 2020, arXiv:2001.06782）

**問題設定**：`K`個のタスク損失`L1,...,LK`の和`L=ΣLi`を最小化するマルチタスク学習。安全制約やCMDPという概念はなく、「タスク」はすべて対等（優先順位や制約の区別がない）。

**対立の定義（Definition 1、原文確認）**：
> "We define θij as the angle between two task gradients gi and gj. We define the gradients as conflicting when cos θij < 0."

**射影公式（Algorithm 1、原文確認）**：対立時（`cos θij<0`）のみ、
```
gi^PC = gi − (gi・gj / ‖gj‖²) gj
```
を、対象となる全ての他タスク`j`について順に適用する（`K=2`の場合は1回のみ）。**対立していない場合は何もしない（射影を適用しない）**。最終的な更新方向は、こうして得られた`gi^PC`（`i=1..K`）の**単純和**（`K=2`なら`g1^PC+g2^PC`）である。

**目的関数・制約条件**：明示的な制約付き最適化問題としては定式化されていない。射影公式はヒューリスティックであり、CAC Eq.10やCAGrad Eq.3のような`argmax`/`argmin`の解として導出されたものではない（Definition 1の対立検出＋射影というルールベースの手続き）。

**ノルム制約・安全性保証**：なし。射影後のベクトルのノルムに上限は設けられていない。

**理論（Theorem 1、原文確認）**：
> "Assume L1 and L2 are convex and differentiable. Suppose the gradient of L is L-Lipschitz... the PCGrad update rule with step size ηt ≤ 1/L will converge to either (1) a location... where cos(φ12)=−1 or (2) the optimal value L(θ*)."

すなわち、凸・Lipschitz条件のもとで、**収束先は「真の最適値」または「2つの勾配が完全に逆向き（cos=−1）になる、劣最適な停留点」のいずれか**であるという、収束は保証するが最適性までは保証しないタイプの定理である。

**理論（Theorem 2、原文確認）**：非凸設定でも、`cos(φ12)≤−δ(g1,g2)`（対立が十分強い）・曲率の下限・学習率の条件（3条件）が同時に満たされれば、PCGrad適用後の損失がバニラ勾配降下より小さくなることを保証する、1ステップの十分条件。

### 1.2 CAGrad（Liu et al., 2021, arXiv:2110.14048）

**問題設定**：PCGradと同じくマルチタスク学習（`K`個の損失`L1,...,LK`、主目的は平均`L0=(1/K)ΣLi`）。

**最適化問題（Eq.3、原文確認）**：
```
max_{d∈R^m}  min_{i∈[K]} ⟨gi,d⟩   s.t.  ‖d−g0‖ ≤ c‖g0‖
```
`g0`は平均勾配、`c∈[0,1)`は事前指定するハイパーパラメータ。**「平均勾配を中心とする半径`c‖g0‖`の球の中で、全タスクの最悪ケース内積（最も改善しないタスク）を最大化する`d`を求める」という、明示的なmax-min制約付き最適化問題**として定式化されている点が、PCGradとの最大の違いである。

**双対問題への還元（Eq.2周辺・Algorithm 1、今回新たに確認）**：`d`はパラメータと同次元（数百万次元になりうる）のため直接解くのは非現実的だが、原文で以下の還元が示されている：

> "It is not practical to directly solve for d on every optimization step. However, the dual problem of Eq. (3)... only involves solving for a decision variable w∈R^K, which can be efficiently found using standard optimization libraries."

具体的には、`w`を`K`次元の確率単体（`Σwi=1, wi≥0`）上の変数として、
```
w* = argmin_{w∈simplex}  g_w・g0 + √λ‖g_w‖   (g_w=Σwi・gi)
```
という**タスク数`K`（通常は2〜数十）次元の凸最適化問題**に帰着させ（`λ=c²‖g0‖²`）、最終的な更新は`d=g0+g_w*/λ^{1/2}・λ`（原文の記法に準拠、詳細な係数は付録A.3参照、本レポートでは未精読）。

**重要な事実**：CAGradは**反復的な数値最適化（`K`次元の凸計画）を毎ステップ解く必要がある**、PCGrad・PCRPO・Ver.1のような閉形式のスカラー計算では完結しない手法である（`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第4.3節の記述を今回のAlgorithm 1確認によって裏付けた）。

**理論（Theorem 3.2、原文確認）**：
> "For any c≥1, all the fixed points of CAGrad are Pareto-stationary points of (L0,L1,...,LK)."（`c<1`の場合はさらに強い保証：`L0`が単調に減少する速度の下限が示される）

**ノルム制約・安全性保証**：`d`のノルムは`g0`を中心とする球に制約されるが、これは「安全制約」ではなく「更新方向が平均勾配から大きく逸脱しない」という多目的最適化上の制約である。

### 1.3 PCRPO（Gu et al., 2024, arXiv:2405.01677）——`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`の再確認

**問題設定（Eq.4、原文確認）**：`max Vr(π) s.t. Vci(π)≤bi (i=1,...,n)`という一般的なCMDP。

**3モード切り替え（原文確認済み、既存レポートと相違なし）**：`Vci(w)`（コスト価値関数の推定値）と閾値`bi+h+`・`bi+h-`の比較により、safety-only（式18）・balanced（式20）・reward-only（式17）を切り替える。

**balanced内部の勾配操作（Eq.6-8、原文確認済み）**：
```
対立時（θ≥90°）: gr+ = gr−(gr・gc/‖gc‖²)gc,  gc+ = gc−(gc・gr/‖gr‖²)gr,  g=(gr++gc+)/2
非対立時（θ<90°）: g = 0.5gr + 0.5gc （固定重み）
```

**重要な事実（式(6)とPCGradの射影公式の同一性、再確認）**：PCRPOの式(6)は、PCGradの射影公式`gi−(gi・gj/‖gj‖²)gj`と**数式として完全に同一の形**である。相違点は、PCGradが対立時にのみ片方向の射影を（`K`個のタスクに対して逐次）適用するのに対し、PCRPOは**対立時に双方向の射影を計算し、その単純平均を取る**という点、および安全制約という非対称な役割分担（`gr`=性能、`gc`=安全）を明示的に導入している点である。

**収束定理（Theorem B.1/B.2、既存レポート`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第2.5節で精読済み）**：Lipschitz連続性の仮定下、`g=(gr++gc+)/2`（式7）または`g=0.5gr+0.5gc`（式8）という**特定の閉形式を代入した証明**により、単調改善を保証する。

**SCRPOアブレーション（第2.7節、既存レポートで確認済み）**：PCRPO自身が、PCGradのAlgorithm 1をそのまま安全RLに適用したベースライン「SCRPO」を実装・比較済みである。

### 1.4 CRPO（Xu, Liang, Lan, 2021, arXiv:2011.05869）——今回初めて本文を精読

**問題設定**：一般的なCMDP（`J0`=報酬、`Ji(i=1,...,p)`=コスト制約、`Ji(w)≤di`）。

**Algorithm 1の構造（原文確認、既存レポートでは未確認だった内容）**：

```
各step tで：
1. 現在の方策w_tのもとで、報酬・全コストの状態行動価値関数を推定（Policy Evaluation）
2. 推定した制約値 J̃i,Bt (i=1,...,p) を計算
3. もし全てのiについて J̃i,Bt ≤ di+ε（許容誤差ε）ならば：
      → 報酬 J0(w_t) を最大化する方向へ「1ステップ」更新
4. そうでなければ（1つ以上の制約が違反）：
      → 違反している制約のうち任意の1つ Jit を選び、
        それを最小化する方向へ「1ステップ」更新
```

**これは本レポートで確認した中で最も重要な構造的事実である**：CRPOは、PCGrad・CAGrad・PCRPOのような「複数の勾配を1つのベクトルに合成する（射影・平均・最適化）」という操作を**一切行わない**。各step、報酬方向かコスト削減方向かの**いずれか一方をそのまま採用する、離散的な二者択一**のみである。勾配の内積・角度・射影といった概念はAlgorithm 1には登場しない。

**理論（Theorem 1、原文確認）**：表形式（tabular）設定でNPGを最適化手法として用いた場合、確率`1-δ`以上で
```
J0(w*) − E[J0(w_out)] = O(1/√T),   E[Ji(w_out)] − di = O(1/√T)   (i=1,...,p)
```
という、**目的関数の劣最適性と制約違反量の両方に対する有限時間の収束率**を証明している（Algorithm 1・13行目の`w_out`は`N0`集合——制約を満たしていたステップの集合——から一様ランダムに選ばれる）。

**CRPOとPCRPOの関係（PCRPO原文、第2.6節で既に確認済み、再掲）**：PCRPOは「CRPOは安全制約に強く違反した場合のみ安全最適化に切り替える」とCRPOを位置づけ、これに対して**PCRPOは勾配の射影・平均という連続的な混合を導入した点が差分である**、と自己位置づけしている。

## 4. 新規性の検討

以下、各主張について、今回確認した文献の範囲での評価を述べる。**文献調査は本レポート・既存レポート合わせて4手法5論文（PCGrad, CAGrad, PCRPO, CRPO, および参考としてのCAC）にとどまり、勾配操作・安全RL分野全体を網羅したものではないため、いずれの項目についても「新規性がある」「新規性がない」と断定はしない。**

### 4.1 「Ver.1のm1はPCGradと同一か」

**確認できたこと（数学的事実）**：`m1`が生成する方向`P=W2_use−(dot12/‖W1‖²)W1`は、PCGradの射影公式`gi−(gi・gj/‖gj‖²)gj`に`gi=W2_use, gj=W1`を代入した式と**数式として厳密に一致する**（第3.1節で再導出、既存レポートと同一結果）。

**確認できたこと（相違点）**：
- PCGradはこの射影を**対立時にのみ**（`cos θ<0`のときのみ）適用し、非対立時は生の勾配をそのまま使う。Ver.1の`m1`はこの条件分岐を持たず、常に計算される値である（対立の有無は`safety_level`・`m2`との混合を通じて間接的にしか反映されない）。
- PCGradは`K`個のタスクに対して**双方向**（各`gi`を他の全`gj`について）射影するが、Ver.1の`m1`は`W2_use`を`W1`の直交補空間へ射影する**一方向のみ**である。
- `m1`は射影`P`そのものではなく、`(1-m1)`という追加のスカラー係数がかかった`e(m1)=(1-m1)P`である（第1.2節参照）。この`(1-m1)`のスケーリングはPCGradには存在しない。

**結論（確認した範囲での判断）**：`m1`が生成する**方向**は、限定的な条件下（本節で述べる相違点を無視した場合）でPCGradの射影公式と数学的に一致するが、`m1`という**係数の使われ方全体**（`(1-m1)`倍、常時計算、`m2`・`safety_level`との混合という文脈）はPCGradと同一ではない。「`m1`がPCGradと同一である」とは断定できない。

### 4.2 「m1はPCRPOの射影処理と同一か」

第4.1節と同様の理由で、方向の一致は確認できる（PCRPOの`gc+=gc−(gc・gr/‖gr‖²)gr`もPCGradと同型）。ただしPCRPOは`gr+`と`gc+`の**両方**を計算し**平均**を取るのに対し、Ver.1は`m1`単独路線（`W1`への射影は行わず、`W2_use`側の射影のみ）である点が異なる。**「m1がPCRPOの射影処理と同一である」とは断定できない**（部分的な数式一致にとどまる）。

### 4.3 「m2は既存手法に対応するか」

`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第2.3節・第4.1.3節（本レポートの表）で確認した通り、**今回確認した4論文のいずれにも`m2`に相当する明示的な式は見当たらなかった**。PCRPOの`gr+`（性能側の射影）とも数式として一致しない（`m2=‖W2‖²/(‖W2‖²−dot12)`という式は、射影公式`gi−(gi・gj/‖gj‖²)gj`の形に代数的に一致するかどうかを確認する必要があるが、`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第2.2節で確認した通り`m2`は`e・W2_use=0`を厳密には満たさないため、少なくとも「`W2_use`を`W1`の直交補空間へ厳密に射影する係数」ではない）。**確認した範囲では、`m2`に対応する既存手法の処理は見当たらない。**

### 4.4 「m_soft・rel_cap・m_scaleの組み合わせに独自性があるか」

`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第6節で確認済みの通り、今回確認した4論文いずれにも、`m_soft`（`m_thresh=100,p=1.5`のソフト閾値）・`rel_cap`（`‖W2_use‖`に比例する相対上限）・`m_scale`（`±21`クランプ）に相当する具体的な機構への言及はなかった。CAGradの球制約`‖d−g0‖≤c‖g0‖`は「大きさを抑制する」という機能面では類似するが、これは**目的関数に組み込まれた制約**であり、Ver.1のような**事後的な非線形変換の合成**とは構造が異なる（第2節の対応表を参照）。**確認した範囲では対応する機構は見当たらないが、ソフト閾値・proximal operator等、最適化理論一般に広く存在する技法との関係は未調査であり、追加の文献調査が必要である**（`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`と同じ結論を維持する）。

### 4.5 「CBFと勾配調整の組み合わせに未検討の可能性があるか」

第1節・第3節で確認した通り、PCGrad・CAGrad・CRPO・PCRPOのいずれもCBFという安全表現を採用していない。したがって、**「CBFという安全表現に対して、この種の勾配調整（射影・混合・ソフト閾値）を適用する」という組み合わせ自体は、今回確認した4論文との関係では重複が確認されなかった**。ただし、これは`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第5節・第8節で既に述べた通り、CBF側の未読文献（arXiv:2505.00671等）でこの組み合わせが扱われている可能性を排除するものではなく、**追加調査が必要**という結論に変わりはない。

### 4.6 「既存手法との差分が単なる実装上の変更にとどまるか」

以下の観点から、単なる実装上の変更以上の差分がある可能性と、逆に本質的でない可能性の両方を、根拠とともに整理する。

**単なる実装上の変更にとどまらない可能性を示す事実**：
- `safety_level`（`h_value`ベースの連続シグモイドゲート）は、PCRPO・CRPOの離散的な閾値切り替えとは時間的・数学的構造が異なる（第2節の対応表）。

- `m_soft`以降のパイプライン全体（第4.4節）に対応する処理が見当たらない。

**単なる実装上の変更にとどまる可能性を示す事実**：

## 5. 理論面の比較

### 5.1 PCGradの理論的性質とVer.1への適用可否

Theorem 1（凸+Lipschitzのもとでの収束）・Theorem 2（1ステップでの損失減少の十分条件、`cos(φ12)≤−δ(g1,g2)`等3条件）は、いずれも**`gi^PC=gi−(gi・gj/‖gj‖²)gj`という特定の射影公式、かつ`K`個のタスクの単純和という更新規則**を前提に証明されている（第1.1節）。

Ver.1への適用可否：**適用できない**。理由は`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第7.2節でPCRPOのTheorem B.1/B.2について述べた理由と同型である——Ver.1の`m_dir`は`m1`,`m2`の**非対称な内分点**（`m`という連続スカラーによるアフィン結合）であり、PCGradの「射影後ベクトルの単純和」という構造そのものと一致しない。加えて、PCGradの証明は損失関数`L1,L2`の凸性を仮定するが、Ver.1のActor損失（SACの方策損失＋安全損失）が凸であるかどうかは本レポートでは未検討である。

### 5.2 CAGradの理論的性質とVer.1への適用可否

Theorem 3.2（`c<1`のもとでPareto定常点への収束、Lipschitz連続性を仮定）は、**`d`が双対問題（`K`次元単体上の凸計画）の解であることに強く依存**する（第1.2節）。

Ver.1への適用可否：**適用できない**。Ver.1の`m1`,`m2`,`m_dir`はいずれも代数的に閉じた式であり、CAGradのような制約付き最適化問題の解として構成されていない。したがって、CAGradの証明の出発点（`d`が最適化問題の解であるという性質）自体が、Ver.1の`e`には成立しない。

### 5.3 PCRPOの安全性・収束に関する主張とVer.1への適用可否

`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第7.2節・第7.3節で既に詳細に検討済みであり、本レポートでも結論に変更はない：Theorem B.1/B.2は`g=(gr++gc+)/2`または`g=0.5gr+0.5gc`という特定の閉形式に依存しており、Ver.1の非対称な`m1`/`m2`混合構造にはそのままでは適用できない。

### 5.4 CRPOの理論的性質とVer.1への適用可否（今回新たに検討）

CRPOのTheorem 1（`O(1/√T)`の目的関数劣最適性・制約違反量の保証）は、**Algorithm 1が「毎stepどちらか一方向へのフルステップ更新」という離散的な構造を持つことに強く依存**する（証明の技術的中核は、`N0`集合——制約を満たしていたstepの集合——の性質を、確率的な「動的切り替えを伴う確率近似過程」として解析する点にある、第1.4節）。

Ver.1への適用可否：**適用できない**。Ver.1は「どちらか一方向」という離散選択を行わず、常に`W1`,`W2_use`の連続的な混合`e`を計算する。CRPOの証明技術（`N0`集合の解析）は、この種の連続混合には直接対応しない構造である。**加えて、CRPOはNPG/TRPO/PPO/SAC等の「方策最適化ステップ」を1つのブラックボックスとして扱い、その内部でActor損失の勾配をどう合成するかには立ち入らない**（Algorithm 1の7行目・10行目は「方策更新を1回行う」としか述べていない）。これは、CRPOの理論的枠組みが、そもそもVer.1・CAC・PCRPOのような「勾配レベルでの合成」という問題設定とは異なる抽象化レベルにあることを意味する。

### 5.5 CAC Eq.10との関係、m1がCAC最適方向と一致する条件（既存の証明結果の要約）

`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`・`M1_M2_CAC_OPTIMALITY_VERIFICATION.md`で既に証明済みの事実（本レポートでは新たな導出は行わず、要約のみ）：

- CAC Eq.10は`D=W1・W2`の符号で場合分けできる閉形式解を持つ：`D≥0`なら`e*=W2`、`D<0`なら`e*=‖W2‖・g2_perp/‖g2_perp‖`。
- `D<0`のとき、`m1`由来の方向は常にCACの真の最適方向`g2_perp`の正のスカラー倍と一致する（`denom1<0⟹m1<1`が`W1≠0`のとき常に成立することから証明済み、2000件のMonte Carlo検証済み）。
- ただし、この一致は**方向のみ**であり、大きさ（`‖e*_CAC‖=‖W2‖`という等号制約）の一致は保証されない。

**本レポートで追加すること**：PCGrad/PCRPOの射影公式との一致（第4.1節・第4.2節）と、CAC Eq.10の`D<0`ケースの解（第5.5節冒頭）は、**同じ数式`gi−(gi・gj/‖gj‖²)gj`を異なる文脈（PCGrad/PCRPOはヒューリスティック、CACは制約付き最適化問題の証明された解）から得ている**という点で、興味深い一致である。すなわち、**「勾配射影というヒューリスティックが、実はCACのような特定の制約付き最適化問題の厳密解と一致する場合がある」ということが、CAC Eq.10の閉形式解の導出（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`）によって示された**、と整理できる。ただしこれはPCGrad/PCRPOの原論文自身が主張していることではなく、**本研究（本レポート・関連レポート群）が独自に行った代数的な橋渡しである**点を明記する。

### 5.6 m_soft・rel_cap・m_scale後にもこの対応関係が維持されるか

`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`第3.4節・第5節で証明済みの通り、**維持されない**。`m_soft`以降の処理は`W2_use・w_dir`という、安全制約`e・W1`とは別の量の符号によって`m_scale`の符号が決まるため、`m1`（または`m_dir`）の段階で成立していた「方向がCACの最適方向と一致する」という関係は、`m_scale`が負の符号を取れば**反転しうる**。この結果は、第5.5節で述べた「射影公式としての理論的な意味」が、Ver.1の実際のパイプライン全体（`m_soft`等の後段処理込み）には及ばないことを意味する。

## 7. Proposal Ver.2への示唆

現時点ではコード変更・実験は行わず、以下を今後の比較実験・評価指標の**候補**として整理する（優先順位は付けない）。

1. **PCGradをベースラインとして実装する必要性**：`m1`経路がPCGrad/PCRPOの射影公式と数学的に一致することが確認されているため（第4.1節）、PCGradをそのままCBFベースの`W1`,`W2`に適用したベースライン実装は、比較的低コストで実現できる可能性がある。ただしPCRPO自身が「SCRPO」として類似のベースラインを既に報告している点（第1.3節・`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第2.7節）に留意し、単純な移植ではなく、CBFという安全表現への適用時に何が変わるかを明確にする必要がある。
2. **PCRPOとの公平な比較条件**：PCRPOの3モード切り替えは`Vci(w)`（長期価値関数）に基づくのに対し、Ver.1は`h_value`（短期移動平均）に基づく。両者を同一の実験設定で比較する場合、**ゲートの入力を揃える（あるいは両方を実装して比較する）**必要があり、そうしないと「手法の違い」と「ゲート入力の違い」が交絡する。
3. **CAGradとの比較可能性**：CAGradは反復的な凸最適化を要するため、Ver.1・PCGrad・PCRPOのような閉形式手法とは**計算コストの性質が異なる**（第1.2節）。比較する場合、単純な学習曲線の比較だけでなく、**1updateあたりの追加計算コスト（勾配計算回数、最適化の反復回数等）を分けて計測する**候補が考えられる。
4. **CRPOとの比較可能性**：CRPOは勾配合成を行わない離散切り替えのみの手法であるため、Ver.1・PCGrad・PCRPOと同じ土俵での比較（射影方向のコサイン類似度等）にはなじまない。CRPOと比較する場合は、**「制約違反量に対する定量的な理論保証の有無」という枠組み**（第3節・第5.4節）での比較が候補になりうる。
5. **m1/m2を既存手法と比較する評価指標の候補**：
   - `D=W1・W2`の符号ごとの発生頻度（CACの対立判定基準）
   - `D<0`のときの実際の`m_dir`と`m1`（CACの真の最適方向に対応する係数）とのコサイン類似度・数値的な近さ
   - 本レポートで導出したCACの真の閉形式解`e*_CAC`（`D`の符号で場合分け）と、Ver.1の実際の最終`e`とのコサイン類似度・ノルム比（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第6節で既に候補として提示済み）
6. **安全性制約の違反率・違反深刻度**：第3節で整理した「勾配方向の制約」（a）と「実験上の安全性評価」（f）を区別した上で、`e・W1<0`となる頻度（勾配レベルの違反）と、実際の環境での安全性指標（`episode_h`,`episode_violations`等）を**別々に**計測・報告する候補。
7. **勾配方向のコサイン類似度**：Ver.1の`w_dir`,`w_scaled`,最終`e`と、PCGrad射影・PCRPO平均・CAC真の解のそれぞれとのコサイン類似度を、同一の`W1`,`W2`データ（既存の診断ログ基盤`diag_shadow.py`系を拡張）で比較する候補。
8. **CAC最適方向との距離**：`e*_CAC`（本レポート第5.5節で参照した閉形式）とVer.1の各段階（`m1`,`w_dir`,最終`e`）との角度・ノルム比の分布を、既存の100-run・Stage B系データで（新規実験なしに）再解析できるか検討する候補（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第6節と同じ提案の再掲）。
9. **計算時間・勾配計算回数**：CAGrad（反復最適化）・PCGrad/PCRPO/Ver.1（閉形式）・CRPO（単純な二者択一、最も軽量）の間で、1updateあたりの追加計算量を分類・計測する候補。CACが単純な閉形式で解ける可能性が高いこと（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第3節）を踏まえると、**「Ver.1の計算量がCACより小さい」という主張自体が現時点では成立しないため**、この指標はVer.1・CAC双方について中立に計測する必要がある。
10. **学習の安定性とseed間のばらつき**：既存の100-run実験のばらつき（9件の外れ値run、`analysis_proposal_ver1_100run/REPORT.md`）を、PCGrad/CRPO等のベースライン実装と比較する候補。

## 8. 事実・数学的導出・仮説の分類まとめ

**【原論文から直接確認できた事実（本レポートで新たに確認したもの）】**
- CRPOのAlgorithm 1が、勾配合成を一切行わない離散的な二者択一であること（第1.4節）。
- CRPOのTheorem 1が、目的関数の劣最適性と制約違反量の両方にO(1/√T)の保証を与えること（第1.4節）。
- CAGradが`K`次元単体上の凸計画への双対還元を必要とし、閉形式では完結しないこと（第1.2節）。
- CAGradのTheorem 3.2がPareto定常点への収束を保証すること（第1.2節）。
- PCGradのTheorem 1・Theorem 2の正確な主張（第1.1節）。

**【既存レポートで確認済みの事実（本レポートで再確認・再利用）】**
- PCRPOのEq.6-8、3モード切り替え、Theorem B.1/B.2、SCRPOアブレーション（第1.3節）。
- `m1`の射影方向がPCGrad/PCRPOの射影公式と数学的に一致すること（第4.1節・第4.2節）。
- CAC Eq.10の閉形式解、`m1`との対応（第5.5節）。

**【本レポートで新たに導出・整理した事実】**
- Ver.1の13要素とPCGrad/CAGrad/PCRPO/CRPOそれぞれとの対応関係の網羅的整理（第2節の表）。
- 「勾配方向の制約」〜「実験上の安全性評価」の6分類による、5手法（CAC含む）の安全性保証の性質の違い（第3節の表）。
- 各理論（PCGrad Thm1/2、CAGrad Thm3.2、CRPO Thm1）がVer.1に適用できない理由の個別の数学的根拠（第5.1節・第5.2節・第5.4節）。

**【断定しない事項（明示的な確認）】**
- 「m1がPCGrad/PCRPOの射影処理と同一である」：方向のみ、限定的な条件下で一致する（第4.1節・第4.2節）。
- 「m2が既存手法に対応する」：確認した範囲では対応が見当たらないが、断定はしない（第4.3節）。
- 「m_soft・rel_cap・m_scaleの組み合わせに独自性がある」：確認した4論文には見当たらないが、最適化理論一般との重複は未調査（第4.4節）。
- 「CBFと勾配調整の組み合わせが未検討である」：確認した4論文との関係では重複なしだが、CBF側未読文献の可能性は排除できない（第4.5節）。
- 「既存手法との差分が単なる実装上の変更にとどまる／とどまらない」：いずれの方向にも断定しない（第4.6節）。
- いずれの手法についても、根拠のない優劣評価は行わない（第6節）。
