## ① 現在のProposal Ver.1の正確な位置づけ

### 1.1 数学的に何を実装しているか

`gradient_blend.py`・`agent.py`から確認できる処理は、以下の通りである（`CAC_VER1_MATHEMATICAL_COMPARISON.md`第3節・`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`第2節の表を統合）。

```
W1=grad_sa（安全性勾配）, W2=grad_st（性能勾配）
W2_use = W2・shrink        shrink=1/(1+log10(‖W2‖+1))
dot12 = W1・W2_use  (=c)
denom1 = c-‖W1‖²(=a)  ; m1 = c/denom1_safe
denom2 = ‖W2‖²(=B)-c  ; m2 = B/denom2_safe
t = clip(progress,0,1)          progress=min(1.0,(episode/stage2_episodes)²)
m_progress = (1-t)m2+t・m1
safety_level(σ) = sigmoid(k(c_thresh-h_value))   k=1.63, c_thresh=0.55
                  h_value = リプレイバッファ一様サンプルの下位15%分位点の直近80回移動平均
m_dir = σ・m1+(1-σ)・m_progress  →  clip(m_dir,min(m1,m2),max(m1,m2))
w_dir = m_dir・W1+(1-m_dir)・W2_use
m0 = (W2_use・w_dir)/‖w_dir‖²
m_soft = sign(m0)・|m0|/(1+(|m0|/100)^1.5)
rel_cap = 4.5・(‖W2_use‖+ε)  ; m_rel = sign(m_soft)・min(|m_soft|,rel_cap)
m_scale = clip(m_rel,-21,21)
w_scaled = m_scale・w_dir  → 400ノルムクリップ → (agent.py)102.5クリップ → 50.0 clip_grad_norm_
```

**明示すべき前提（ユーザー指示に基づき強調）**：`config.py`で`stage1_episodes=0`である。これは「CACのStage1を実行した上で撤廃した」のではなく、**Stage1に相当する学習を一度も実行していない**ことを意味する。`agent.py`にはStage1用の分岐がコード上残っているが、`stage1_episodes=0`により恒久的に発火しない。学習はepisode 1から一貫して、CACでいうStage2相当の処理（`restricted_direction()`による勾配混合）のみで行われる。

### 1.2 CACの制約付き最適化と一致している部分・一致していない部分

CAC Eq.10（`argmax_e e・∇J2(θ) s.t. e・∇J1(θ)≥0, ‖e‖≤‖∇J2(θ)‖`、`CAC_EQ10_SOURCE_VERIFICATION.md`でPDF画像により確定済み）の閉形式解は、`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`・`M1_M2_CAC_OPTIMALITY_VERIFICATION.md`で導出・独立検証済みである：`D=W1・W2≥0`なら`e*=W2`、`D<0`なら`e*=‖W2‖・g2_perp/‖g2_perp‖`（`g2_perp=W2-(D/a)W1`）。

**一致している部分（証明済みの事実）**：
- `D<0`のとき、`m1`が与える方向`P=W2_use-(c/a)W1`は`s・g2_perp`（`s>0`はshrink係数）に等しく、`denom1<0⟹m1<1`が`W1≠0`のとき常に成り立つため、`e(m1)=(1-m1)・s・g2_perp`は**CACの真の最適方向と常に正のスカラー倍で一致する**（2000件のMonte Carlo検証済み、`M1_M2_CAC_OPTIMALITY_VERIFICATION.md`）。

**一致していない部分（証明済みの事実）**：
- **大きさ**：CACの真の解は`‖e*‖=‖W2‖`を常に満たすが、`m1`段階の`e(m1)`のノルムがこれと一致する保証はない。
- **`D≥0`の場合**：CACの解は`e*=W2`（無加工）だが、Ver.1のパイプラインは`D`の符号による明示的な分岐を持たず、`m1`にこの場合の特別な意味はない。
- **`m2`**：CACのいずれの解領域にも対応しない（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第2.3節）。安全制約`e・W1≥0`を常には満たさず、`m2`使用時の符号は`sign(‖W2_use‖²-dot12)`と一致する（`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`第3.2節）。
- **最終更新方向**：`m_soft`・`rel_cap`・`m_scale`の符号は`sign(W2_use・w_dir)`で決まり、`sign(w_dir・W1)`とは独立であるため、`m1`段階で成立していた「CACの方向と一致する」という関係は**最終的な`e`には及ばない**（`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`第3.4節・第5節、証明済み）。
- **数値的な例外経路**：`denom1`/`denom2`が`(-eps,0)`にあると`denom_safe`が厳密に0になり`m1`/`m2`が`±inf`化する非対称なゼロ除算、および`restricted_direction()`の早期リターン文（複数）が正常系のタプルと異なる単一テンソルを返すため`agent.py`側のアンパックが`ValueError`を起こしうる構造的な不整合が存在する（`DENOM_NUMERICAL_STABILITY_ANALYSIS.md`）。ただし、これまでに実測された106 run（100-run本番＋Stage B系6 run）ではいずれも発生していない。
- **安全性保証の前提条件**：CACのTheorem 1はStage1完了時の`V1(s0)≈0`を前提とする（`CAC_VER1_MATHEMATICAL_COMPARISON.md`第1.5節・第6.3節）。Ver.1は`stage1_episodes=0`によりこの前提を満たさないため、**Theorem 1が条件付きでも適用される根拠がそもそも存在しない**（推測ではなく、Theorem 1の前提条件とVer.1の設定を直接突き合わせた結論）。

### 1.3 既存研究と共通する要素

`PCRPO_PCGrad_CAGrad_DETAILED_COMPARISON.md`・`CBF_GRADIENT_LITERATURE_REVIEW.md`・`CBF_REWARD_COMPARISON.md`で確認済みの事実を整理する。

- `m1`が与える方向は、PCGrad（arXiv:2001.06782）の射影公式`gi-(gi・gj/‖gj‖²)gj`、およびPCRPO（arXiv:2405.01677）の`gc+`と数式として同型である。
- `W1`/`W2`という非対称な役割分担（安全・性能）は、PCRPOの`gr`/`gc`分離と構造的に近い（PCGrad/CAGradは複数タスクを対等に扱うため、この非対称性を持たない）。
- CBF前方不変性条件の書き換え`raw=h(s')+(α-1)h(s)`は、今回確認した全てのCBF系論文（BLAC, Cheng et al., log-sum-exp論文, CBF-RL）に共通する標準形である。
- `exp(x)-1`という報酬変換の関数形自体は、CBF-RL（arXiv:2510.14959）にも存在する（ただし引数の中身は異なる——Ver.1はCBF条件の違反量そのもの、CBF-RLは行動修正前後の距離）。
- 2つの独立した価値推定（性能・安全）を持つという構造は、PCRPO/CRPOの`Vr`/`Vci`分離と概念的に共通する。

### 1.4 現時点で主張できること・できないこと

**現時点で主張できること**：
1. `D<0`のとき、`m1`の方向はCACの真の最適方向と常に正のスカラー倍で一致する（証明済み、`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`・`M1_M2_CAC_OPTIMALITY_VERIFICATION.md`）。
2. Ver.1の勾配調整は反復ソルバーを伴わない代数演算のみで完結する（コード上明らかな事実）。
3. `m_soft`以降の多段階非線形処理は、今回確認した8論文（PCRPO, PCGrad, CAGrad, CRPO, BLAC, Cheng et al., log-sum-exp論文, CBF-RL）のいずれにも直接対応する機構が見当たらない。
4. Stage B/Stage B-extendedにより、`m1`/`m2`が桁違いに発散する事例（`denom1`/`denom2`の近ゼロ化）が実在し、`m_soft`が少なくとも観測した事例では最終ベクトルのノルムを抑えていることを実測で確認した。

**現時点で主張できないこと**：
1. `m1`がCAC Eq.10全体（両制約込み）の厳密解であること（方向のみ、`D<0`限定で一致）。
2. Ver.1の最終更新方向が安全制約`e・W1≥0`を常に満たすこと（`m2`優勢時・`m_scale`の符号反転時に破れうることを証明済み）。
3. Ver.1がCACと同等の安全性保証（Theorem 1相当）を持つこと（Stage1を実行していないため前提が満たされない）。
4. Ver.1の計算量がCACより必ず小さいこと（CAC自身も`D`の符号のみで場合分けできる単純な閉形式で解ける可能性が高く、比較対象であるCAC側の実際の計算コストが未確定）。
5. 勾配射影・ブレンドという発想自体、およびCBFとの組み合わせが新規であること（前者はPCGrad/PCRPOとの重複度が高く、後者は今回確認した文献範囲では重複が見当たらないという消極的な結果にとどまる）。

## ② 研究課題候補の再整理

既存3レポート（`RESEARCH_DIRECTION_REPORT.md`の候補1〜5、`RESEARCH_QUESTION_OPTIONS.md`の候補A〜D、`MASTER_THESIS_RESEARCH_PLAN.md`の案1〜4）を、重複を統合した上で7つに整理し、それぞれを6観点（数学的な明確性／既存研究との差分検証可能性／実装可能性／修論としての適切性／将来的な学術論文への発展可能性／実験規模・計算時間の現実性）から記述する。ランキング・点数付けは行わない。

### (a) CACの計算負担・乖離の定量評価（旧候補5・D、案1〜4の統合）

CACのRestricted Policy Updateの真の閉形式解（本研究で既に導出済み）とVer.1の`m1`/`m2`混合との乖離、および両者の計算コストを定量比較する。

- **数学的な明確性**：高い。CAC側の閉形式解は既に導出・独立検証済み（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`）であり、乖離の定義（コサイン類似度・ノルム比）も明確に構成できる。
- **既存研究との差分検証可能性**：高い。CAC自身との比較であるため「既存研究との重複」という観点よりも「CACとの数量的な差分」を直接示せる。ただし、CAC側の実際の計算コスト（原論文がEq.10をどう解いているか）は未確認であり、これが判明するまで「計算コスト削減」という主張の比較対象自体が確定しない（`RESEARCH_PRIORITY_PLAN.md`項目6、`CAC_VER1_MATHEMATICAL_COMPARISON.md`第1.4節）。
- **実装可能性**：中〜高。乖離評価は既存の`diag_shadow.py`基盤に`e*_CAC`の計算を追加するだけで、既存の100-run・Stage B系データの再解析で実施できる可能性が高く、大規模な新規実験が不要（`M1_M2_CAC_OPTIMALITY_ANALYSIS.md`第6節で候補として提示済み）。計算コスト比較には`update_critics_and_actor()`の段階別プロファイリングという軽量な追加実装で足りる（`MASTER_THESIS_RESEARCH_PLAN.md`案4）。CAC本来の凸最適化実装との比較を含める場合は、追加のCAC再現実装（`runs_cac/`は現状1 runのみ）が必要になり、実装コストが上がる。
- **修論としての適切性**：高い。研究目的（「CACの計算負担軽減」）と直接対応する、最も中心性の高いテーマである。
- **将来的な学術論文への発展可能性**：中〜高。CAC Eq.10の閉形式解の導出自体は本研究独自の貢献であり、「ヒューリスティックが最適解にどう関係するか」という定量分析は査読論文の主張として成立しうる構成である。
- **実験規模・計算時間の現実性**：高い（既存データの再解析中心）。ただしCAC本来実装との比較を含める場合は現実性がやや下がる。

### (b) m_soft吸収現象の理論解析と数値安定性問題（旧候補1・A、`DENOM_NUMERICAL_STABILITY_ANALYSIS.md`の統合）

`m1`/`m2`の発散を`m_soft`が吸収する現象の数学的な成立条件・破綻条件を解析し、あわせて`denom_safe`の非対称なゼロ除算・早期リターン文の型不整合という、実装上発見された数値安定性の問題を扱う。

- **数学的な明確性**：中〜高。`m_soft`自体は閉形式の合成関数であり解析可能だが、一般的な成立条件の証明は非自明（`RESEARCH_DIRECTION_REPORT.md`候補1で「中〜高」と評価済み）。数値安定性の問題（`denom_safe`の非対称性、戻り値の型不整合）は既に代数的に確認済み（`DENOM_NUMERICAL_STABILITY_ANALYSIS.md`）。
- **既存研究との差分検証可能性**：中。今回確認した8論文いずれにも`m_soft`型の機構は見当たらなかったが、proximal operator・soft-thresholding等の最適化理論一般との関係は未調査であり（`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第8節、継続課題）、この調査を経ないと差分の主張が完結しない。
- **実装可能性**：高い。既存の`diag_shadow.py`基盤を用いた合成入力での数値実験が中心であり、新しいアルゴリズム実装は不要。
- **修論としての適切性**：中〜高。理論色が強く、数理的考察力を示す構成になる。ただし研究目的の中心（計算負担軽減）とは直接結びつかないため、(a)と組み合わせる、または独立した副次的貢献として位置づける必要がある。
- **将来的な学術論文への発展可能性**：中。Ver.1固有の現象の解析であり直接の競合文献は少ないと見られるが、一般的な飽和関数理論に帰着する可能性があり、貢献の独自性の範囲を慎重に見極める必要がある。
- **実験規模・計算時間の現実性**：高い（合成入力による数値実験が中心、実環境での大規模実験は不要）。

### (c) CBF安全学習アーキテクチャの比較（旧候補B）

同一のCBF条件・同一環境・同一SACを前提に、①行動空間QP射影（Cheng et al., log-sum-exp論文型）、②Augmented Lagrangian罰則（BLAC型）、③報酬合算＋単一Critic（CBF-RL型）、④Ver.1型（報酬分離＋2Critic＋勾配ブレンド）を統一的に比較する。

- **数学的な明確性**：中。各アーキテクチャの数式自体は明確だが、公平な比較条件（ハイパーパラメータの整合等）の設計に検討を要する。
- **既存研究との差分検証可能性**：高い。個々の先行研究はいずれも自身のアーキテクチャのみを評価しており、「アーキテクチャの選択自体を独立変数として扱う比較」という構図自体は、今回確認した範囲の文献には見当たらなかった（`RESEARCH_QUESTION_OPTIONS.md`候補B）。
- **実装可能性**：中〜低。4アーキテクチャ全ての実装・公平な比較実験の設計は、他候補より実装・実験コストが大きい（`RESEARCH_QUESTION_OPTIONS.md`第8節で明記済み）。
- **修論としての適切性**：中。比較研究としての価値は高いが、実装範囲が広いため、修論の期限内に完遂できるかは実装コスト次第である。
- **将来的な学術論文への発展可能性**：高い。体系的なアーキテクチャ比較は、Safe RL分野において引用されやすい構成になりうる。
- **実験規模・計算時間の現実性**：中〜低。4アーキテクチャ×複数run（`MASTER_THESIS_RESEARCH_PLAN.md`第4節の考え方に従えば、まず少数run→分散を見て本実験run数を決定）が必要であり、他候補より重い。

### (d) 安全度ゲートの時間スケール比較（旧候補C）

`h_value`（短期移動平均）とPCRPOの`Vci(π)`・BLACの`L(x_t)`（長期価値関数）を、同一のゲート関数`safety_level=sigmoid(k(c-x))`への入力として比較する。

- **数学的な明確性**：中。ゲート関数自体は単純だが、長期価値関数側の実装（別Criticの学習）が必要。
- **既存研究との差分検証可能性**：中〜高。時間スケールの選択自体を比較した先行研究は見当たらなかった（`RESEARCH_QUESTION_OPTIONS.md`候補C）。
- **実装可能性**：中。`h_value`計算部分のみを差し替えたVer.1亜種として実装できるため、(c)よりは限定的な変更で済む。
- **修論としての適切性**：中。`ADDITIONAL_INVESTIGATION.md`で指摘済みの`h_value`の構造的問題（学習初期データへの引きずられ）と接続でき、ストーリーの一貫性はあるが、単独では研究目的（計算負担軽減）との結びつきが弱い。
- **将来的な学術論文への発展可能性**：中。
- **実験規模・計算時間の現実性**：中〜高（既存100-run基盤・診断ツールを流用可能）。

### (e) h_value・ゲート機構の再設計（旧候補4）

`h_value`の分位点設計・移動平均窓幅を再設計し、性能を比較する。

- **数学的な明確性**：中。
- **既存研究との差分検証可能性**：中。適応的Lagrangian乗数手法（PID-Lagrangian等）との概念的な重複可能性があり、要比較検討（`RESEARCH_DIRECTION_REPORT.md`候補4）。
- **実装可能性**：中。
- **修論としての適切性**：中。「指標を変えて性能が上がった」という工学的改善にとどまるリスクがあり、「なぜ現在の設計が構造的に不適切か」の実証（既存の診断結果）との接続が必須（`RESEARCH_DIRECTION_REPORT.md`第5.2節で既に指摘済みの回避策）。
- **将来的な学術論文への発展可能性**：中〜低。単独ではハイパーパラメータ変更に近い印象を与えるリスクが指摘されている。
- **実験規模・計算時間の現実性**：高い（既存基盤を流用可能）。

**この候補は(d)と密接に関連するが、(d)は「入力の時間スケール」という観点、(e)は「同じ短期統計量の中でのパラメータ設計」という観点であり、(d)を実施する場合は(e)がそのアブレーションの一部として自然に組み込める。**

### (f) 評価時安全性・違反重大度指標の設計（旧候補3）

決定論的方策での評価専用ロールアウト、違反の重大度指標（`-h(next_state)`の平均・最大値等）を新たに導入する。

- **数学的な明確性**：中。指標設計自体は単純な統計量の追加。
- **既存研究との差分検証可能性**：低〜中。Safe RLの評価指標設計に関する既存研究との重複可能性が高く要調査（`RESEARCH_DIRECTION_REPORT.md`候補3）。
- **実装可能性**：高い。アルゴリズム自体は変更せず、評価フェーズ・指標計算の追加のみ。
- **修論としての適切性**：単独テーマとしてはやや弱い。**`RESEARCH_QUESTION_OPTIONS.md`第4節「補足」で既に指摘済みの通り、候補(a)〜(d)いずれを選んでも共通して必要になる実験基盤として位置づける方が整合的**であり、本レポートでもこの整理を維持する。
- **将来的な学術論文への発展可能性**：低〜中（単独では弱いが、他候補の評価節の一部として寄与）。
- **実験規模・計算時間の現実性**：高い。

### (g) 安全制約充足率の実証評価とPCGrad/PCRPO等との比較（新規統合、旧候補2の発展形）

`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`で証明済みの「`e・W1<0`になりうる」という事実の実測頻度を、既存データの再解析、およびPCGrad型の明示的射影・PCRPO型の平均射影を実装したベースラインとの比較で評価する。

- **数学的な明確性**：高い。`e・W1`の符号を決める条件式は既に導出済み（`CAC_CONSTRAINT_SATISFACTION_ANALYSIS.md`第3.4節）であり、測定すべき量が明確。
- **既存研究との差分検証可能性**：中〜高。PCRPO自身が「SCRPO」としてPCGrad直接適用のベースラインを既に報告しているため（`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第2.7節）、単純な移植では新規性が薄いが、**CBFベースの設定でこれを行った比較、および「勾配内積の非負性」と「実際の環境安全性」を明確に区別した評価**は、今回確認した文献には見当たらない構図である（`PCRPO_PCGrad_CAGrad_DETAILED_COMPARISON.md`第3節・第7節）。

- **将来的な学術論文への発展可能性**：中〜高。
- **実験規模・計算時間の現実性**：中（既存データの再解析部分は高いが、ベースライン実装を含めると中程度に下がる）。

## ③ 研究課題の候補を3つに絞る

②の7候補のうち、(f)は独立候補ではなく共通基盤として位置づけ、(e)は(d)のアブレーションとして統合する方針を維持した上で、**研究目的（CAC計算負担軽減、SAC+CBF、r_nav/r_safe分離、2Critic、m1/m2勾配調整、2段階撤廃、安全性・性能両立）との対応の強さ、既存の数学的成果（(a)(b)(g)はいずれも本研究で既に大部分の理論的下地がある）の活用度、実装コストの現実性**を踏まえ、以下の3候補に絞る。

### 候補①：CAC計算負担・乖離の定量評価（②の(a)を中心に、(g)の安全制約充足率評価を統合）

- **研究目的**：CACのRestricted Policy Updateが要求する制約付き最適化の真の解と、Proposal Ver.1の`m1`/`m2`混合ヒューリスティックとの間の乖離（方向・大きさ・安全制約充足）、および両者の計算コストの構造的な違いを定量的に明らかにすることを目的とする。
- **解決したい問題**：現状、「Ver.1がCACの計算負担を軽減する」という主張は、閉形式ヒューリスティックである（反復ソルバー不要）という構造的事実のみに基づいており、(i)乖離の大きさ、(ii)比較対象であるCAC自身の実際の計算コスト、のいずれも定量化されていない。
- **提案手法の概要**：本研究で既に導出済みのCAC Eq.10の閉形式解（`D≥0`なら`e*=W2`、`D<0`なら`e*=‖W2‖g2_perp/‖g2_perp‖`）を診断基盤（`diag_shadow.py`系）に追加し、既存の100-run・Stage B系データから、Ver.1の各段階（`m1`,`w_dir`,最終`e`）とCACの真の解とのコサイン類似度・ノルム比・安全制約充足率（`e・W1≥0`の頻度）を再解析する。あわせて、`update_critics_and_actor()`の段階別プロファイリングにより計算時間の内訳を測定する。
- **比較対象となる既存手法**：CACの真の閉形式解（本研究で導出）、CAC原論文の（解法未確認の）Restricted Policy Update、可能であればPCGrad型の直接適用。
- **必要な数学的検証**：CAC原論文がEq.10を実際にどのような手続き（数値ソルバー／閉形式）で解いているかの再確認（現状「本文に明記なし」というのが確認済みの事実であり、これ以上の確認は原論文の再読以外に手段がない）。`m2`とPCRPOの`gc+`の対応関係の確認（未検証のまま残っている、`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第9節）。
- **必要な実験**：既存データの再解析（新規実験は最小限で済む可能性が高い）。計算時間プロファイリングは軽量な追加実装で対応可能。CAC本来実装との比較まで含める場合は、`runs_cac/`（現状1 run）の拡充が必要になる可能性がある。
- **想定されるリスク**：CAC側の実際の計算コストが原論文から確認できない場合、「計算コストを削減した」という主張の比較対象自体が確定しないまま研究を進めることになるリスクがある。また、乖離が大きい場合（`m_soft`以降で方向が反転する等）、「近似として機能している」という前提そのものが崩れる可能性がある——ただしこれは研究上望ましくない結果ではなく、それ自体が正確に報告すべき知見である。
- **新規性を主張するために必要な追加調査**：CAC原論文の関連研究章の再読（他手法への言及の有無）、CAC計算コストに関する記述の有無の最終確認。

### 候補②：m_soft吸収現象の理論解析と数値安定性問題の体系的整理（②の(b)）

- **研究目的**：`m1`/`m2`の発散を`m_soft`が吸収する現象の数学的な成立条件・破綻条件を明らかにし、あわせて実装上発見された数値安定性の問題（`denom_safe`の非対称なゼロ除算、早期リターン文の型不整合）を体系的に整理することを目的とする。
- **解決したい問題**：現状、`m_soft`の吸収現象は5事例の実測（Stage B-extended）でのみ確認されており、一般的な数学的保証がない。また、`denom_safe`の非対称性・戻り値の型不整合という、これまでの実験（106 run）では顕在化していないが理論上存在する脆弱性が未整理のままである。
- **提案手法の概要**：`m_soft`を含む合成関数（`m0→m_soft→rel_cap→m_scale`）の入出力関係を、`diag_shadow.py`基盤を用いた広範な合成入力（`W1`,`W2`,`progress`,`h_value`を走査）でのシミュレーションと、解析的な証明の試みの両面から特徴づける。`denom_safe`の非対称性が実際にどのような`W1`,`W2`の分布のもとで発生しうるかを理論的に整理する。
- **比較対象となる既存手法**：直接の比較対象となる先行研究は今回確認した8論文には見当たらないため、比較の枠組みとして「一般的な飽和関数・proximal operator・soft-thresholding」を暫定的な参照点とする（未調査、追加文献調査が前提）。
- **必要な数学的検証**：`m_soft`の吸収が成立する一般条件（現状は5事例の実測のみ）。`denom1`/`denom2`が`(-eps,0)`に入る条件が、実際の`W1`,`W2`の分布のもとでどの程度の確率で起こりうるかの理論的評価。
- **必要な実験**：合成入力によるシミュレーション（新規の大規模実験は不要、既存基盤の再利用が中心）。
- **想定されるリスク**：「発散する入力を飽和させる」という性質自体が、最適化理論一般の既知の性質に帰着する場合、独自性の主張できる範囲が狭くなる。また、数値安定性の問題（`denom_safe`等）を修正した場合に吸収現象自体の性質が変わる可能性があり、修正の要否の判断が研究の途中で必要になりうる（本レポート時点では修正は行わない）。
- **新規性を主張するために必要な追加調査**：proximal operator・soft-thresholding等、最適化理論・信号処理分野の一般文献の調査（未着手、`LITERATURE_AND_MATHEMATICAL_COMPARISON.md`第8節から継続する課題）。

### 候補③：CBF安全学習アーキテクチャの比較（②の(c)、(d)をアブレーションとして含める）

- **研究目的**：同一のCBF条件・環境・SACを前提とした場合に、安全性の実現機構（行動空間QP射影／Augmented Lagrangian罰則／報酬合算＋単一Critic／Ver.1型の勾配ブレンド）の選択が、安全性・性能・計算コストのトレードオフにどう影響するかを明らかにすることを目的とする。
- **解決したい問題**：個々の先行研究（Cheng et al., BLAC, CBF-RL等）はいずれも自身のアーキテクチャのみを評価しており、同一条件下でのアーキテクチャ間の比較が存在しない。また、安全度ゲートの時間スケール（短期移動平均 vs 長期価値関数）の選択自体を比較した先行研究も見当たらない。
- **提案手法の概要**：同一の`h(s)`・同一の`raw=h(s')+(α-1)h(s)`条件を全アーキテクチャで固定し、報酬変換・勾配生成・パラメータ更新の段階のみを変えた変異体を実装して比較する（`MASTER_THESIS_RESEARCH_PLAN.md`第4節のA〜F変異体設計を参照可能）。時間スケールの比較（②の(d)）は、Ver.1型アーキテクチャ内でのゲート入力（`h_value` vs 長期価値関数）の差し替えとして、このアーキテクチャ比較のアブレーションに位置づける。
- **比較対象となる既存手法**：Cheng et al. (arXiv:1903.08792)型のQP射影、BLAC (arXiv:2304.04066)型のAugmented Lagrangian、CBF-RL (arXiv:2510.14959)型の報酬合算、Ver.1型の勾配ブレンド。
- **必要な数学的検証**：各アーキテクチャの安全性保証の性質の違い（`PCRPO_PCGrad_CAGrad_DETAILED_COMPARISON.md`第3節の6分類——勾配方向の制約／更新後の安全性／CBF条件／状態遷移安全性／理論保証／実験評価——を各アーキテクチャに適用して整理する）。
- **必要な実験**：4アーキテクチャ×複数run（`MASTER_THESIS_RESEARCH_PLAN.md`の考え方に従い、まず少数run(3〜5程度)で分散を確認した上で本実験run数を決定）。決定論的方策による評価専用フェーズの追加（候補①③共通で必要）。
- **想定されるリスク**：実装・実験コストが3候補の中で最も大きい。公平な比較条件（各アーキテクチャのハイパーパラメータ調整の程度をどう揃えるか）の設計が難しく、比較結果の解釈に恣意性が入るリスクがある。修論の期限内に4アーキテクチャ全ての実装・複数run実験を完遂できない可能性がある。
- **新規性を主張するために必要な追加調査**：CBF側の未読文献（SafePG: arXiv:2609.14076等）の確認、CBF-RLのTable II（報酬重みの具体値）の確認。

**3候補の関係についての整理**：候補①は研究目的の中心（計算負担軽減）に最も直接的に対応し、既存の数学的成果（CAC閉形式解の導出）を最大限活用できる。候補②は候補①の副次的な理論的貢献として組み込むことも、独立した理論色の強い章として扱うことも可能である。候補③は最も実装コストが高いが、修論の主要な実証的貢献として、候補①の乖離評価・候補②で整理した安全性保証の分類を統合的に活用できる構成になりうる。**3つ全てを同格の独立候補として同時に完遂する必要はなく、候補①を中心に据え、候補②・③を候補①の理論的背景・実証的拡張として部分的に取り込む、という組み合わせ方も選択肢である**（この組み合わせ方自体の当否は研究者自身の判断事項とする）。

## ④ 最終的な研究課題の表現案

以下は、現時点で断定できる範囲にとどめた、修士論文に使用できる研究目的・研究課題の文章案である。「新規性がある手法を開発した」という断定は避け、「〜を目的とする」「〜を検証する」「〜の可能性を検討する」という表現を用いる。

**案1（候補①を中心とした表現）**：
> 本研究は、Control Barrier Function（CBF）に基づく安全報酬とSoft Actor-Criticを組み合わせた安全強化学習において、Certificated Actor-Critic（CAC）のStage 2で用いられる制約付き最適化（Restricted Policy Update）を参考に設計した勾配調整手法（`m1`/`m2`混合）が、当該最適化問題の閉形式解とどのような関係にあるかを数学的に明らかにし、両者の乖離および計算コストの構造的な違いを定量的に検証することを目的とする。

**案2（安全制約充足の実証評価を明示した表現）**：
> 本研究は、安全性勾配と性能勾配を代数的に混合する勾配調整手法（Proposal Ver.1）について、当該手法が生成する更新方向がCACの安全制約（安全性勾配との内積の非負性）をどのような条件下で満たし、どのような条件下で満たさないかを数学的に整理した上で、実際の学習データにおける制約充足の実態を検証することを目的とする。

**案3（m_soft理論解析を中心とした表現、候補②）**：
> 本研究は、勾配調整パイプラインに含まれる非線形なソフト閾値処理（`m_soft`）が、混合係数の数値的発散を最終的な更新ベクトルのノルムの範囲でどのように抑制しているかを数学的に整理し、その成立条件・限界条件、および関連する数値安定性の課題を明らかにすることを目的とする。

**案4（アーキテクチャ比較を中心とした表現、候補③）**：
> 本研究は、同一のCBF安全条件を、行動空間での射影・Lagrangian型の罰則・報酬合算・勾配ブレンドという異なる学習アーキテクチャで扱った場合に、安全性・性能・計算コストのトレードオフがどのように異なるかを、統一的な実験条件のもとで検証することを目的とする。

**案5（研究全体を包括する表現）**：
> 本研究は、SACとCBFを組み合わせた安全強化学習において、CACのStage 2の制約付き最適化を参考にした勾配調整手法（r_nav/r_safeの分離、2Critic構造、m1/m2による勾配混合、2段階構造の撤廃を含む）が、計算負担・安全性・性能の観点でCAC本来の構成、および既存の勾配操作手法（PCGrad, PCRPO等）とどのような数学的・実証的な関係にあるかを検証することを目的とする。ここで「勾配調整」という発想自体の新規性は主張せず、CBFベースの設定における当該手法の具体的な数学的性質・実証的な挙動の解明に主眼を置く。

いずれの案も、候補①〜③のどれを主軸にするか、あるいは組み合わせるかによって、対応する文言の重みづけを調整する必要がある。

## ⑤ 次に行うべき調査・作業（依存関係順）

4. **候補①〜③（またはその組み合わせ）の選定**：段階1の結果を踏まえ、研究者自身が主軸とする候補を確定する。これ以降の作業は、選定結果に応じて内容が分岐する。

### 段階3：実装・評価基盤の整備（候補によらず共通に必要）
