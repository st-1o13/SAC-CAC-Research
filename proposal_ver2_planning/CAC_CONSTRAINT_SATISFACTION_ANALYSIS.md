## 1. CAC Eq.10の制約条件（再掲・区別して明記）

【コード・論文から確認できる事実】（`CAC_EQ10_SOURCE_VERIFICATION.md`でPDF画像により確認済み）

CAC Eq.10は以下の**2つの制約**から成る：

- **安全制約**：`e・∇θJ1(θ) ≥ 0`
- **ノルム制約**：`‖e‖ ≤ ‖∇θJ2(θ)‖`

この2つは独立した制約であり、本レポートでは以降「安全制約」と「ノルム制約」を明確に区別して扱う。

**重要な留保**：Proposal Ver.1の`W1`（`grad_sa`）・`W2`（`grad_st`）が、CAC論文の`∇θJ1(θ)`・`∇θJ2(θ)`と数学的に完全に一致する対象であるかは**未確認**である。具体的には、`CAC_VER1_MATHEMATICAL_COMPARISON.md`第2節で確認した通り、CACの`r1`はEq.12で`exp(min(...,0))∈(0,1]`と定義されるのに対し、Ver.1の`r_safe`は`exp(min(...,0))-1∈[-1,0]`という異なる正規化を用いる。またCACの`r2`はEq.9でCLF（制御Lyapunov関数）`l(s)`に基づく例が示されているのに対し、Ver.1の`r_nav`はPendulum-v1環境の標準報酬をそのまま用いる。したがって、**`W1`↔`∇θJ1(θ)`、`W2`↔`∇θJ2(θ)`という対応付けは、役割（安全性損失の勾配・性能損失の勾配）としての構造的な類似性に基づくものであり、両者が同一の数式・同一の数値を持つことは証明されていない**。以降の議論はこの対応付けを**作業仮説**として進める。

## 3. 安全制約`e・W1≥0`を満たすための必要条件・十分条件

### 3.1 一般恒等式（数学的に導出）

【数学的に導出できること】：`e=m・W1+(1-m)・W2_use`という形の任意のスカラー`m`について、

```
e・W1 = m・a + (1-m)・c = c - m・(c-a) = c - m・denom1
```

という**恒等式**が成り立つ（`m`について線形）。この恒等式は`w_dir`段階まで一貫して適用できる。

### 3.2 各係数での`e・W1`の値（数学的に導出）

- **`m=m1`のとき**：`e・W1 = c - m1・denom1 = c - c = 0`（`m1`の定義そのものから自明）。
- **`m=m2`のとき**：`e・W1 = c - m2・denom1`を整理すると、

  ```
  e・W1(m2) = (a・B - c²) / denom2
  ```

  という式が得られる（本レポートで導出）。分子`a・B-c²`は、コーシー・シュワルツの不等式（`c²=(W1・W2_use)²≤a・‖W2_use‖²=a・s²B≤a・B`、`s≤1`より）から**常に`≥0`**であることが保証される。したがって、

  ```
  sign(e・W1(m2)) = sign(denom2) = sign(B-c)
  ```

  が成り立つ。これは`B>c`（`‖W2‖²`が`W1・W2_use`より大きい）ときのみ非負になり、**常に安全制約を満たすわけではない**。

- **`m=m_progress`のとき**：`e・W1`が`m`について線形であることから、

  ```
  e・W1(m_progress) = (1-t)・(e・W1(m2)) + t・(e・W1(m1)) = (1-t)・(a・B-c²)/denom2
  ```

  となる（`m1`の寄与は0）。

### 3.3 `m_dir`クランプ後の`e・W1`の範囲（数学的に導出・本レポートの中心的な結果）

【数学的に導出できること】：`e・W1`は`m`の**線形関数**であり、`m_dir`（クランプ後）は必ず区間`[min(m1,m2),max(m1,m2)]`に収まる。線形関数は区間の端点で最小値・最大値を取るため、

```
e・W1(w_dir) ∈ [ min(0, V), max(0, V) ]  ,  V = (a・B-c²)/denom2
```

が**常に成り立つ**（`m_dir`が`m1`,`m2`のどちらに近いか、`safety_level`・`progress`の具体的な値によらず、この区間の中に収まることが保証される）。

**この主張が成立するために必要な前提（確認・明記）**：

1. **線形性**：`e・W1=c-m・denom1`が`m`について線形であること（第3.1節、`e=m・W1+(1-m)・W2_use`という定義から常に成り立つ、無条件の事実）。
2. **`m1`・`m2`の定義**：`m_dir`（クランプ後）が区間`[min(m1,m2),max(m1,m2)]`に収まることは、コード上の`torch.clamp(m_dir, min=float(m_min), max=float(m_max))`という処理そのものから直接保証される（`m1`,`m2`はコードが実際に計算した値であり、後述のepsilon代入が発動していてもこの区間保証自体は成り立つ）。
3. **`m_progress`の影響**：`m_progress=(1-t)m2+t・m1`、および`m_dir`（クランプ前）`=σ・m1+(1-σ)・m_progress`は、いずれも`m1`と`m2`の**係数の和が1になる凸結合**である（`σ+(1-σ)t`と`(1-σ)(1-t)`を足すと1になることを確認できる）。したがって、**`m_dir`はクランプを適用する前の時点で、既に`m1`と`m2`の凸結合として`[min(m1,m2),max(m1,m2)]`の区間内に入っている**。コード上のクランプ処理は、この意味では理論上冗長（no-op）である可能性が高いが、浮動小数点演算の誤差に対する安全策として機能していると考えられる。

**epsilon代入に関する重要な留保**：`e・W1(m1)=0`という値、および`e・W1(m2)=(a・B-c²)/denom2`という具体的な式は、`m1=c/denom1_safe`・`m2=B/denom2_safe`の計算において、コード上のepsilon安全代入（`|denom1|<eps`または`|denom2|<eps`のとき`denom_safe`に置き換える処理）が**発動していない**場合（すなわち`|denom1|≥eps`かつ`|denom2|≥eps`の場合）に限り厳密に成り立つ。**`Stage B`・`Stage B-extended`で確認された`m1`/`m2`の発散事例は、まさにこのepsilon代入が発動する（分母が近ゼロ化する）局面であり、そのような局面では`e・W1(m1)`が厳密に0からわずかにずれる可能性がある**。ただし、区間に収まるという構造的な主張（`e・W1(w_dir)`が`e・W1(m1)`と`e・W1(m2)`の間にあるという線形性に基づく議論）自体は、`m1`,`m2`がどのような値（epsilon代入後の値であっても）であっても無条件に成立する。

**これが`w_dir`段階（`m_soft`以降の処理が適用される前）における、安全制約充足の必要十分条件に相当する事実である**（以下、epsilon代入が発動していない場合の具体的な値`V=(a・B-c²)/denom2`を用いて記述する）：

- `denom2>0`（`V≥0`）ならば、区間は`[0,V]`となり、**`e・W1(w_dir)≥0`が常に成立する**（十分条件：`denom2>0`）。
- `denom2<0`（`V≤0`）の場合、区間は`[V,0]`となり、`e・W1(w_dir)`は0以下になりうる。この場合に`e・W1(w_dir)≥0`となるのは、`m_dir`がちょうど`m1`（区間の`0`側の端点）に一致する場合に限られる。

### 3.4 `m_scale`適用後（`w_scaled`）の符号——本レポートで新たに確認した重要な事実

【数学的に導出できること】：`w_scaled=m_scale・w_dir`は`w_dir`の**スカラー倍**であるため、

```
w_scaled・W1 = m_scale・(w_dir・W1)
```

が成り立つ。ここで`m_scale`の符号は`m_rel`→`m_soft`→`m0`の符号を経由して決まる。`gradient_blend.py`のコード（`torch.sign`の仕様：`sign(0)=0`）を直接数値検証したところ、**`m0=0`ならば`m_shrunk=0`→`m_soft=0`→`m_rel=0`→`m_scale=0`という連鎈が厳密に成立する**ことを確認した（本レポート作成にあたり`torch.sign(torch.tensor(0.0))`等で実際に検証済み）。すなわち、

```
sign(m_scale) = sign(m0) = sign(W2_use・w_dir)     （0は0に対応する、という意味を含む）
```

が常に成り立つ。**この`sign(W2_use・w_dir)`は、`sign(w_dir・W1)`とは独立な、別の量である**。

**必要十分条件の整理（ゼロを含む全ケースを区別して記述する）**：

`w_scaled・W1=m_scale・(w_dir・W1)`は2つの実数の積である。積`x・y≥0`となるのは、`x`,`y`が同符号（両方`≥0`または両方`≤0`）のとき、およびどちらかが0のときである。この一般的な事実を今回のケースに適用すると、以下のように場合分けできる。

- **`m_scale≠0`かつ`w_dir・W1≠0`の場合**：`w_scaled・W1≥0 ⟺ sign(m_scale)=sign(w_dir・W1) ⟺ sign(W2_use・w_dir)=sign(w_dir・W1)`（両者が非ゼロかつ同符号）。
- **`m_scale=0`の場合**（`⟺W2_use・w_dir=0`）：`w_scaled=m_scale・w_dir=0`（零ベクトル）となるため、`w_scaled・W1=0`となり、**`w_dir・W1`の値によらず`w_scaled・W1≥0`は常に成立する**（この場合、実質的にActorへの更新量そのものが0になる、という退化したケースである点に注意）。
- **`w_dir・W1=0`の場合**（`m_scale`の値によらず）：`w_scaled・W1=m_scale・0=0`となり、**`m_scale`の符号によらず`w_scaled・W1≥0`は常に成立する**。

**一般的な必要十分条件（全ケースを統合した、正確な記述）**：

```
w_scaled・W1 ≥ 0
  ⟺  [ W2_use・w_dir = 0 ]
     ∨ [ w_dir・W1 = 0 ]
     ∨ [ sign(W2_use・w_dir) = sign(w_dir・W1)  かつ両者は非ゼロ ]
```

**簡略化した符号条件（実務上の近似的な言い換え、限界を明記）**：前回のレポート版では、この条件を単純に「`sign(w_dir・W1)=sign(W2_use・w_dir)`（またはいずれかが0）」と記述していたが、この表現は**`sign(0)=0`という規約のもとで「両方0」の場合は正しく扱えるものの、「片方だけが厳密に0」の場合（例：`w_dir・W1=0`だが`W2_use・w_dir≠0`）を正しく含めていない**という不正確さがあった。この場合、`sign(w_dir・W1)=0`かつ`sign(W2_use・w_dir)=±1`であり、両者の符号（`sign`関数の値）は一致しないが、実際には`w_scaled・W1=m_scale・0=0≥0`が成立するため、簡略化した表現では「条件を満たさない」と誤って判定されてしまう。**したがって、簡略化した符号条件は、`m_scale`と`w_dir・W1`の両方が厳密に非ゼロである場合にのみ、上記の一般的な必要十分条件と一致する近似表現として扱うべきであり、ゼロを含む境界的なケースについては、必ず上記の3分岐（`m_scale=0`／`w_dir・W1=0`／両方非ゼロで同符号）に立ち返って判定する必要がある。**

**この条件は、`W1`・`W2_use`・`w_dir`の具体的な数値関係に依存しており、一般には常に成り立つとは限らない。現状のコード・数式だけからは、この条件が学習中にどの程度の頻度で成立するかを判定できない。実測データによる追加検証が必要である（第8節参照）。**

### 3.5 最終クリップ（400／102.5／50.0）の影響

【コード・論文から確認できる事実、および数学的に導出できること】：この3段階のクリップはいずれも「ノルムが閾値を超えたら、正のスカラー`(閾値/現在のノルム)`を乗じる」という処理であり、**方向を変えない正のスカラー縮小**である。したがって、`w_scaled・W1`の符号は、これら3段階のクリップを経ても**変化しない**（第6節で詳述）。

**結論（本節のまとめ）**：最終的な`e`が`e・W1≥0`を満たすかどうかは、実質的に**第3.4節で整理した一般的な必要十分条件（`W2_use・w_dir=0`、または`w_dir・W1=0`、または両者が非ゼロで同符号）によって決まる**。これらのいずれも成立しない場合（すなわち`m_scale`と`w_dir・W1`が非ゼロかつ異符号の場合）、`m_soft`以降のクリップ処理では符号を修正できず、最終的な`e`は安全制約を満たさない。

## 4. m1・m2の意味の再確認

【コード・論文から確認できる事実、および数学的に導出できること】：

1. `m1`は`e・W1=0`という**等式条件**に由来する係数であり、この点は本レポートおよび`CAC_VER1_MATHEMATICAL_COMPARISON.md`で代数的に確認済みである。
2. `m1`が**CAC Eq.10全体（安全制約の不等式＋ノルム制約の両方を考慮した制約付き最適化問題）の厳密解であるとは断定しない**。`CAC_VER1_MATHEMATICAL_COMPARISON.md`第5.1節で述べた通り、`m1`は安全制約が境界で有効（`e・∇J1(θ)=0`）な場合の解に対応する可能性があるという**仮説**にとどまる。
3. **`m1`がノルム制約`‖e‖≤‖∇θJ2(θ)‖`を独立に満たす保証があるか**：【現時点では未確認の仮説】。`m1`の段階では`e`のノルムはまだ`m_soft`以降のクリップを経ておらず、`W2_use`は`shrink`（`s≤1`）を経た量であるため、`‖∇θJ2(θ)‖`（CACの記法では生の`W2`のノルムに相当すると考えられる）と`m1`段階の`e`のノルムを直接比較する根拠は、現状のコード・数式だけからは得られない。この点は判定不能であり、実測データでの追加検証が必要である。
4. **`m2`が安全制約を常に満たすか**：第3.2節で導出した通り、**常には満たさない**（`sign(e・W1(m2))=sign(B-c)`であり、`B<c`のとき負になる）。これは仮説ではなく、代数的に導出された事実である。

## 5. m_soft・rel_cap・±21クランプの影響（3分類）

| 処理 | 安全制約を保証する処理か | 安全制約を壊す可能性がある処理か | 単に数値発散を抑える処理か |
|---|---|---|---|
| `m_soft`（ソフト閾値） | 否 | **可能性あり**（`m0`の符号次第で`m_scale`の符号が決まり、`w_dir・W1`の符号と一致しない場合、最終的な`e・W1`の符号を反転させうる：第3.4節） | 主たる機能はこちら（`m1`/`m2`の発散を吸収することは`STAGE_B_EXTENDED_REPORT.md`で実測確認済み） |
| `rel_cap` | 否 | `m_soft`の符号をそのまま引き継ぐため、符号反転のリスクは`m_soft`由来のものと同じ | `|m_soft|`が`rel_cap`を超える場合の追加的な大きさの抑制（`Stage B-extended`診断では`rel_cap`が実際に発動する事例は`m_dir`異常とは別の局面で確認済み） |
| `±21`クランプ（`m_scale`） | 否 | `m_rel`の符号をそのまま引き継ぐため、符号反転のリスクは変わらない | `|m_rel|`が21を超える場合の追加的な大きさの抑制 |

**まとめ**：`m_soft`・`rel_cap`・`±21`クランプの3段階は、**いずれも安全制約`e・W1≥0`を積極的に保証する設計にはなっていない**。これらは`w_dir`の**大きさ**を抑制する処理であり、`w_dir`に乗じるスカラー`m_scale`の**符号**は`W2_use・w_dir`という、安全制約`e・W1`とは別の量によって決まる。したがって、これらの処理は「安全制約を壊す可能性がある処理」に分類され、同時に「数値発散を抑える処理」でもあるという、**両方の性質を併せ持つ**と整理するのが正確である。

## 6. 勾配クリッピングの影響（方向を保つ一様スカラー縮小 vs 成分ごとの変更）

【コード・論文から確認できる事実、および数学的に導出できること】：

1. **400ノルムクリップ**（`gradient_blend.py`内）：`w_scaled`全体に対して`(400/‖w_scaled‖)`という単一のスカラーを乗じる。**方向を保つ一様スカラー縮小**であり、成分ごとに異なる係数を適用するものではない。`e・W1`の符号は不変。
2. **102.5クリップ**（`agent.py`）：同様に`e`全体に単一のスカラー`(102.5/‖e‖)`を乗じる。**方向を保つ一様スカラー縮小**。符号不変。
3. **50.0 `clip_grad_norm_`**（`agent.py`、Actor全パラメータ）：この処理は`e`を各パラメータ`p.grad`に分解した**後**に適用されるが、`torch.nn.utils.clip_grad_norm_`は全パラメータの勾配を**1つの結合されたベクトルとみなして全体のノルムを計算し**、そのノルムが閾値を超える場合に**全パラメータへ同一のスカラー**`(50/‖全体‖)`を乗じる（PyTorchの標準的な仕様）。`e`を各パラメータへ分解して再結合する操作は全単射（値を変えない再配置）であるため、この処理も実質的に**元の`e`ベクトル全体への一様スカラー縮小と数学的に等価**であり、成分ごとに異なる係数をかけるものではない。したがって`e・W1`の符号は不変。

**結論**：`gradient_blend.py`・`agent.py`に存在する3段階のクリップ処理（400／102.5／50.0）は、**いずれも「方向を保つ一様スカラー縮小」に分類され、`e・W1`の符号を変化させない**。符号が変化しうるのは、これらのクリップより前の段階、すなわち`m_scale`が`w_dir`に乗じられる時点（第3.4節）のみである。

## 8. 研究上の意味——Proposal Ver.2で追加すべき検証項目

本レポートの数学的整理により、「Ver.1の最終更新方向がCACの安全制約を満たすかどうか」は、**代数的に一般解を与えることができず、実際の`W1`・`W2`・`w_dir`の数値関係に依存する**ことが明らかになった。したがって、以下の実測的な検証項目が研究上重要になると考えられる。

1. **`e・W1`の符号分布**：既存の`update_log`データ（`diag_shadow.py`系の基盤で拡張可能）を用いて、最終的な`e`と`W1`の内積の符号を全updateについて集計し、負になる頻度を定量化する。
2. **CAC安全制約の違反率**：上記1を「制約違反」として定義した場合の違反率を、既存の100-run・Stage B-extendedのデータで（新規実験なしに）再解析できるか検討する。
3. **ノルム制約の確認**：各段階（`m1`単体、`w_dir`、`w_scaled`、最終`e`）のノルムと、`‖∇θJ2(θ)‖`（`W2`の生のノルムに対応すると考えられる量）を比較し、ノルム制約`‖e‖≤‖∇θJ2(θ)‖`が実際にどの程度満たされているかを確認する。
4. **クリッピング前後の内積の比較**：`w_dir・W1`、`w_scaled・W1`、最終`e・W1`を同一updateについて並べて記録し、第3.4節で示した符号反転が実際に発生する頻度を確認する。
5. **`W1`・`W2`の定義とCACの勾配との対応確認**：`r_safe`・`r_nav`の具体的な式の違い（第1節）が、`∇J1(θ)`・`∇J2(θ)`との対応関係にどの程度影響するかを、CAC論文の枠組みに沿った実装（`runs_cac/`の拡充等）と突き合わせて確認する。

いずれも本レポートでは実施していない。これらは新規のログ・再解析コードの追加を伴うため、実施の要否は別途判断が必要である。
